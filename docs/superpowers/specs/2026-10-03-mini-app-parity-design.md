# 记金小程序与 iOS App 功能对齐

日期：2026-10-03（Asia/Shanghai）
状态：待用户审阅；尚未开始实现。

## 1. 用户要求与完成标准

把当前 App 的全部功能实现到微信小程序中。界面沿用 App 的深色金色风格；唯一明确的功能替换是 Apple 原生登录改为小程序微信登录，手机号与邮箱认证保留。计算规则、字段、交互结果、数据来源、账户隔离和云同步行为均对齐。

迁移基准是本次检查的 `sumly_ios/Sumly/Sources/` 工作区代码，包含尚未提交的现有功能；README 的早期功能描述不作为完整清单。现有 iOS 与 Go 工作区改动须保留，不能重置或用旧提交覆盖。实施期间若 App 继续增加功能，记录变化并补充对齐清单。

“完整”以逐项验收为准，不能以页面存在、mock 演示或构建成功代替。App 里尚未开放的首页订阅与记账入口保持同样的提示行为。已实现的持仓目标提醒属于迁移范围，不得与首页尚未开放的订阅入口混淆。

## 2. 方案选择

采用现有 `uni-app + Vue 3 + TypeScript` 工程，复用 Go 后端，按业务模块移植 Swift 纯逻辑并复现页面。这样保留 H5 联调能力、微信工程与现有数据契约，避免维护另一套后端。

不选择重新建设原生微信工程：会增加两套小程序工程的维护与认证迁移成本。也不采用 WebView 包装 H5：会改变小程序登录、手势和离线存储体验，难以作为完整功能对齐的交付。

## 4. 模块边界与数据流

- `src/api/`：行情、认证、用户与持仓快照；所有请求消费真实 `{ code, message, data }` 契约。
- `src/types/`：行情品种/单位/采样、会话、持仓文档与提醒配置类型。
- `src/domain/`：收益、盈亏拆解、部分处置、筛选排序、日历、日期参考价规则、提醒触发、图表区间与抽样、云文档校验与三方合并。纯 TS，无页面或网络依赖。
- `src/stores/`：账户与代际、行情口径、持仓工作区、同步状态和提醒生命周期。
- `src/utils/`：请求、持久化、日期、跨端工具；仅使用 `uni.*` 与适用的 Vue 能力。
- `src/pages/<domain>/components/`：页面专用图表、表单、持仓卡片、日历等；稳定跨页控件放 `src/components/`。
- 页面只负责生命周期、状态展示、导航和事件编排，不直接实现业务公式与同步算法。

图表采用跨 H5/微信的 canvas 渲染边界，坐标变换、触摸选点、视窗和绘制抽样独立为纯逻辑。任何微信 canvas 节点访问必须通过 uni-app 的组件/节点能力实现，不引入浏览器 DOM 依赖。Vue 运行时组件直接从 `.vue` 文件导入。

行情服务在前台按 App 实际实现刷新，后台暂停、恢复立即刷新。所有请求绑定品种/页面代际；切换口径期间原数据保留，目标口径完整准备后原子替换，不混显不同单位的数据。

## 5. 计算与时间口径

Swift 纯逻辑移植到 TS，并以同一组输入/输出样例验证两端一致。金额展示才舍入，核心计算与云文档保留原精度；非法数值不进入缓存或参与计算。

收益规则：有效克数 = 克数 × 纯度；成本 = 实付总额（若填写）或克数 × 单价 + 总工费 + 其他费用；预计回收单价 = max(0, 参考价 − 每克扣减) × (1 − 折价率)；预计到手 = max(0, 有效克数 × 回收单价 − 固定费用)；真实盈亏 = 到手 − 成本。保本反推、组合保本二分计算、盈亏拆解与已卖出实收严格沿用 App 算法。实付总额不能重复叠加工费。

部分处置沿用 App 成本分摊及 purchaseID 关联，保留总重量与总成本，日历购入件数按购入编号去重。卖出盈亏按实收，赠送按成本记录，不混入当前持仓估值。

交易日以明确日期键处理；跨端转换不能把日期漂移到前一天。持仓事件保存用户指定精确时间；云文档日期使用 Unix 毫秒 Double，兼容已有小数毫秒。国际历史价采用最新有效汇率折算，明确不是历史人民币成交价。休市和缺失日期不补点。

实时样本容差沿用 App 的 max(20 秒, 采样周期 × 2)，报价超过 180 秒标记暂停；暂停保留真实窗口、日期和查价数据。提醒另外沿用 300 秒有效报价、异常跳变过滤、穿越基线与 24 小时冷却规则，不能用图表暂停阈值替代。

## 6. 账户与微信认证补齐

当前微信接口 `POST /auth/wechat/login` 签发旧 JWT，仅足以登录、资料和持仓访问；现有 `/auth/me`、刷新、服务端退出和注销使用独立的有状态认证会话。不能把旧 JWT 当作可刷新或可注销的会话。

推荐增加兼容的微信会话登录接口 `POST /auth/wechat/session`：接收 `js_code`，服务端换取 openid，复用现有微信用户 ID，签发与手机号/邮箱相同结构的 access/refresh 会话。保留现有 `/auth/wechat/login` 契约，避免破坏旧小程序。

在现有认证模块中扩展 verified identity 的 `wechat` provider，通过下一编号数据库迁移扩展 provider 约束。微信身份以配置的小程序 appid 与其 openid 为范围，禁止跨 appid 误绑定。提供商能力接口增加微信可用性；微信重新验证、刷新、退出和最近 5 分钟重验后的注销均走统一会话机制。手机号与邮箱沿用现有已验证身份和接口。

旧微信用户迁移只复用其既有用户 ID，不复制或重新归属持仓；资料字段与会话显示字段明确适配，不将可编辑手机号当已验证身份。原有 legacy token 恢复时保持既有账户缓存，拿到有效微信会话后再升级，不能静默转移游客记录。

微信、手机号、邮箱之间不按昵称、可编辑资料或相同邮箱自动合并。使用原有手机号/邮箱登录可访问相同 App 账户。仅 Apple 登录的账户在小程序中没有替代凭据，不能因为使用微信而自动访问其数据；身份绑定或账户合并是另一项需求，不在此次登录替换中隐式加入。

注销重验必须绑定原账户 ID/provider 与请求代际；重验成另一个用户时不能删除原用户或新用户。退出取消旧请求及刷新，保留当前账户未同步缓存并切回独立游客工作区。凭据只存专属会话存储，不存密码、验证码或微信 code；日志不输出 token/密钥。

## 7. 持仓存储与同步

复用 `/holdings` 的 `schemaVersion: 1` 文档和全部字段，不能以小程序简化模型丢掉 App 字段。UUID 大小写无关比较；记录状态使用 `holding/sold/gift`。历史 assetType 原样保留。books、records、alerts、数值、日期、文本和响应大小限制与服务端一致。

持久化分别保存 `guest` 与 `user:<id>` 工作区，以及同步 revision、base document、本地 document。持久化更新应保证 base 与 revision 同一提交单元，写入失败不得误报保存/同步成功。

登录不自动上传游客数据。显式导入使用原 UUID 去重，保留游客原记录；退出和换号不重新归属缓存。云端 409 后获取新快照并三方合并，不直接覆盖。关联购入与其部分卖出/赠送记录按同一合并单元处理。真正冲突由用户选择本机或云端版本，非冲突自动合并。

每次同步绑定用户 ID 和 sessionGeneration，切换账户/注销后的旧响应不得写入任何缓存。离线编辑可保存，恢复后同步；卸载/清理小程序存储仍按平台本地存储边界处理，未同步更改不能声称已上云。

## 8. 持仓提醒的平台适配

App 目前只在前台监测持仓目标，进入后台停止；小程序保持同样的检测时机，不新增后台价格监控。四种目标、阈值、穿越、冷却、口径、配置同步与送达失败重试规则保持一致。

小程序前台提供同等可见的提醒反馈；系统级送达使用微信订阅消息适配。订阅授权只由用户保存/启用提醒的操作发起。微信模板、授权与发送结果是实际平台能力，不能用成功提示或 mock 替代。

若接入微信订阅消息，需要在后端提供能力状态与账户绑定的发送边界。账户来自会话，收件人 openid 由服务器掌握，不接受任意客户端收件人；发送前重算已保存的持仓配置并验证有效报价，避免任意消息发送。成功前不消耗基线/冷却，失败保留可重试状态。重复请求需幂等。配置不足、授权拒绝和发送失败均显示真实状态。

真实模板与平台授权未就绪时，这一验收项保持未完成，不能宣称“除 Apple 外全部一致”。具体模板字段须在实施阶段根据实际可用模板核对；这是环境接入依赖，不是删减提醒功能的许可。

## 9. 后端范围与错误处理

行情和持仓复用当前契约；后端改动集中于微信统一会话及通知适配所需能力，保持 Go 六边形架构。不因本次迁移重写已有市场读写分离或持仓模块。

认证 401 做一次受账户代际保护的刷新；仍失败要求重新登录，不无限重试。冻结账户保留数据并拒绝读写。网络故障保留缓存，区分真实缓存时间与实时数据。服务不可用不返回假验证码或模拟成功。用户重复提交由明确 loading 状态和幂等边界保护。

mock 模式必须覆盖整个新增业务链路，未覆盖接口直接报错，不回落真实服务器。真实联调以 mock 关闭为准。H5 无微信登录时保留手机号/邮箱以及仅开发环境的测试入口。

## 10. 实施分段与验收

以下为同一完整交付的内部实施顺序，不代表允许只交付其中一段：

1. 固化 App 对齐样例与数据契约；主题、导航和组件基础。
2. 行情服务、历史缓存与增量同步、图表与全套交互。
3. 持仓数据模型、收益内核、增删改与账本、部分赠卖、详情与拆解。
4. 日历、买前计算器、情景测算及目标提醒。
5. 微信会话后端、手机号/邮箱认证、账户生命周期、云同步及冲突处理。
6. 微信通知接入、跨端联调与全清单验收。

核心验证包括两端数值样例一致、费用/纯度/实付覆盖、零值与缺失报价、部分处置守恒、日历去重、提醒穿越与失败重试、云合并/删除冲突/购入族冲突、异步切号/退出/注销隔离、历史手动价保护、跨日/跨午夜/休市图表。

小程序执行纯逻辑测试、`bun run type-check`、`bun run build:h5`、`bun run build:mp-weixin`。后端新增行为先测试后实现，执行 Go 单测、vet 和构建；数据库集成只使用显式 TEST_DATABASE_URL 的随机隔离 schema。

使用 H5 与微信开发者工具逐页操作和截图核对当前 App，真机验证 canvas 手势、输入键盘、日期选择、安全区、微信登录及通知。构建成功不能替代微信运行验证。微信 appid/域名/模板与服务能力不齐时明确记录未通过项。

交付附逐项对齐记录，分别标明自动验证、实际运行验证与环境阻塞；不留无行为按钮，不使用生产假数据。现阶段只制定规格，不部署后端、不上传微信版本、不执行真实用户注销。
