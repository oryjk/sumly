# Sumly 真实收益功能 UI / 交互方案

> 版本：V1.0  
> 日期：2026-09-30  
> 关联 PRD：`docs/gold-real-return-prd.md`  
> 目标：在不破坏现有 Sumly「深色 + 金」设计语言和记金习惯的前提下，把真实收益能力自然融入现有 iOS App。

---

## 1. 交互设计结论

本次不重构 Sumly 整体导航。

现有底栏继续保持：

- 动态
- 记金
- 中央「+」
- 记账
- 我的

**不新增“工具”Tab。**

“买前算一算”作为「记金」场景的核心入口，放在记金页资产总览卡中。

原因：

1. 买前计算与黄金持仓强相关，不需要成为一级导航。
2. 当前底栏已经有 4 个业务入口 + 中央新增按钮，再增加 Tab 会增加认知负担。
3. 用户进入“记金”页，本身就是最容易产生“我现在赚多少 / 再买一笔划不划算”需求的地方。

# 2. 核心用户路径

## 路径 A：已有持仓用户

```text
记金
 ↓
看到「现在卖预计到手」
 ↓
看到「真实盈亏 / 保本状态」
 ↓
点击资产卡
 ↓
真实收益详情
 ↓
查看“怎么算的”
 / 设置提醒
 / 情景测算
```

目标：**3 秒知道结果，1 次点击知道原因。**

---

## 路径 B：准备买黄金

```text
记金
 ↓
买前算一算
 ↓
输入克重 / 报价 / 工费
 ↓
立即看到综合成本 + 保本价
 ↓
修改参数比较
 ↓
购买后「保存为持仓」
```

不要求先创建持仓。

---

## 路径 C：快速记一笔

保持现有中央「+」入口：

```text
+
 ↓
添加黄金
 ↓
填写克重 + 购买价格 + 时间
 ↓
保存
```

高级参数不阻塞普通记账。

## 3.1 顶部区域

- 当前账本

- 隐私金额开关

不增加额外顶部导航。

---

## 3.2 资产总览卡

### 当前结构

```text
总重量
     120.00

购入总价    预估价值    预估收益

记金日历    添加黄金    赠卖记录
```

### 调整后

```text
现在卖预计到手                     👁

¥ 86,420.00

真实盈亏
+ ¥ 3,280.00   +3.94%

────────────────────

持有 102.6g        总投入 ¥83,140

● 已超过真实保本线 ¥32 / g     >
  按当前回收规则估算

[ 买前算一算 ]       [ 添加黄金 ]
```

### 视觉层级

第一视觉：

> **¥86,420.00**

这是整个卡片唯一的大号金额。

第二视觉：

> +¥3,280 / +3.94%

使用国内习惯：

- 盈利：`GoldTheme.up`
- 亏损：`GoldTheme.down`

第三视觉：

- 总克重
- 总投入
- 保本状态

### 为什么不再把“总重量”作为最大数字

Sumly 从普通攒金工具向“资产真实收益工具”升级后，用户最关心的核心结果应当变成：

> **现在真正卖掉大约能拿多少钱？**

重量仍然保留，但降为二级信息。

# 5. 首页快捷操作

# 8. 「怎么算的？」Bottom Sheet

点击后从底部弹出。

建议使用 medium / large detent。

内容：

```text
真实收益怎么算？

当前参考金价             ¥872.67/g
回收扣减                  -¥8.00/g
预计回收价                ¥864.67/g

持有克重                   30.00g
预计回收到手            ¥25,940.10

────────────────────

购买裸金成本            ¥22,200
工费                     ¥2,400
其他费用                     ¥0
总投入                  ¥24,600

────────────────────

真实盈亏
¥25,940.10 - ¥24,600
= +¥1,340.10

[ 修改回收参数 ]
```

交互原则：

- 默认显示人能读懂的计算步骤。
- 不首先显示数学公式。
- 金价来源和更新时间放在底部辅助说明。
- 用户修改参数后，关闭 Sheet 即时刷新详情。

# 10. 买前计算器

入口：

「记金」资产卡 → **买前算一算**

使用 Sheet 打开。

原因：

- 是一个临时任务。
- 完成后可以直接关闭返回记金。
- 保存为持仓时再进入正式数据体系。

## 10.1 初始界面

```text

准备买多少？
[ 30.0 ] g

商家报价
[ ¥850 ] / g

工费
[ ¥120 ] / g

────────────────────

¥29,100

综合买入成本
¥970 / g

真实保本金价
¥1,032 / g

当前参考价还需上涨
+21.4%

[ 保存为持仓 ]
```

# 12. 设置提醒

入口：

持仓详情 → `设置提醒`

不要让用户自己先理解“价格阈值”。

优先提供语义化选项：

```text
提醒我

○ 真正保本时
○ 真实收益达到 5%
○ 真实盈利达到 ¥1,000
○ 金价达到 ¥900/g
```

用户选择后再出现对应输入框。

默认：

- 不自动开启
- 不默认发送营销类通知

# 16. 对现有代码的直接影响

## 保留

- `GoldRootView` 当前底栏
- `HoldingsView` 页面主体
- `AddHoldingSheet` Sheet 模式
- `GoldTheme` 深色 + 金主题
- SwiftData 本地持仓
- 国内红涨绿跌
- 当前行情服务
- 当前账本、搜索、批量管理、日历、赠卖能力

## 调整

### `HoldingRecord`

需要新增真实收益相关字段，例如：

- assetType
- purity
- laborFee
- liquidationRule / override

具体字段在实现阶段结合 SwiftData 迁移确定。

### `HoldingsStats`

从当前：

```text
totalValue
profit
profitPercent
```

升级为统一的真实收益计算模型。

所有页面必须复用同一纯函数计算内核。

### `HoldingsView`

资产总览卡重新排序视觉层级：

```text
总重量
→
现在卖预计到手
```

### `AddHoldingSheet`

从平铺字段改为：

```text
基础录入
+
完善真实收益（折叠）
```

# 17. 实现时的 UI 验收标准

1. 用户打开记金页，不点击任何地方就能知道当前真实盈亏。
2. 首页最大数字只有一个，不出现 3~4 个金额争抢视觉焦点。
3. 新用户只填克重、价格、日期就能完成记录。
4. 高级用户可以填写完整工费和回收参数。
5. 每一个“真实收益”数字都能通过一次点击找到计算依据。
6. 买前计算从打开到得到结果，不超过 3 个核心输入。
7. 用户不需要理解“净清算价值”等专业术语。
8. 不新增一级 Tab，不破坏现有导航习惯。
9. 所有新增视觉继续使用 `GoldTheme` token。
10. 交互保持 SwiftUI 原生行为，不为了炫技增加复杂动画。

# 18. 第一阶段建议实现页面

正式开发建议按以下顺序：

1. **记金首页资产总览卡**
2. **真实收益详情 / 持仓详情**
3. **“怎么算的” Bottom Sheet**
4. **添加黄金渐进式表单**
5. **买前计算器**
6. **情景测算**
7. **提醒**

前三项完成后，Sumly 的核心产品差异已经可以被用户直接感知。

后续再做 Widget、OCR、Live Activities。
