# Sumly 黄金真实收益系统 UI / 交互方案

> 版本：V1.0  
> 日期：2026-10-01  
> 状态：原型已确认，可作为后续 iOS 实现依据  
> 对应 PRD：`docs/gold-real-return-prd.md`

## 1. 设计结论

本轮不重构 Sumly 已稳定的底部导航，继续保留：

- 动态
- 记金
- 中间新增按钮
- 记账
- 我的

真实收益能力主要融入现有「记金」模块，而不是增加新的一级 Tab。

核心交互原则：

1. 先给结果，再给计算过程。
2. 首页只突出一个核心金额：**现在卖预计到手**。
3. 新增持仓继续保持简单，高级参数渐进展开。
4. 所有估算明确标记，避免把估算回收价表达成真实成交价。
5. 高频操作尽量位于拇指容易触达的位置。
6. 延续现有 Sumly「深色 + 金色」视觉语言，不做独立的新设计体系。

## 2. 记金首页

### 2.1 核心资产卡

原有持仓汇总升级为真实收益资产卡。

第一视觉重点：

> 现在卖预计到手 ¥XX,XXX

辅助信息：

- 真实盈亏
- 真实收益率
- 总持有克重
- 总投入

「预计到手」必须带轻量的「估算」标识。

点击核心资产卡进入「持仓详情」。

### 2.2 真实保本状态

资产卡下方单独展示：

> 已超过真实保本线 ¥XX / g

或：

> 距离真实保本还差 ¥XX / g

同时展示：

- 当前参考金价
- 真实保本金价

可使用轻量进度线表达「买入成本 → 保本线 → 当前价格」之间的位置关系。

点击该区域打开「怎么算的？」Bottom Sheet。

### 2.3 今日变化

真实保本状态下方弱化展示：

> 今日价格变化带来的持仓变化 +¥XXX

该信息视觉优先级必须低于真实盈亏。

### 2.4 快捷操作

首页提供两个主要入口：

- **记一笔**
- **买前算一算**

「记一笔」保持主操作。

「买前算一算」作为新功能的重要入口。

### 2.5 我的黄金

单笔持仓列表至少展示：

- 名称 / 品牌
- 购买日期
- 总投入
- 现在卖预计到手
- 真实盈亏
- 真实收益率

点击进入持仓详情。

## 3. 持仓详情

页面顶部展示持仓基础身份：

- 名称
- 品牌
- 购买日期
- 持有时间

### 3.1 第一视觉层

核心结果：

> 真实盈亏 +¥X,XXX

辅助：

- 真实收益率
- 账面价值

同时展示两个核心指标卡：

- 现在卖预计到手
- 真实保本金价

### 3.2 怎么算的？

核心结果区域提供：

> 怎么算的？

点击打开 Bottom Sheet。

Bottom Sheet 按「参数 → 公式 → 结果」展示：

- 当前参考金价
- 数据口径
- 更新时间
- 有效克重
- 纯度
- 每克回收扣减
- 比例折价
- 固定费用

公式示例：

```text
预计到手 = (当前参考金价 - 每克扣减) × 有效克重 - 固定费用

真实盈亏 = 预计到手 - 总投入
```

底部必须提示：

> 当前结果为估算，真实成交价可能因渠道、纯度、检测和手续费变化。

### 3.3 快捷操作

持仓详情提供：

- 情景测算
- 设置提醒
- 编辑
- 标记卖出

## 4. 新增 / 编辑持仓

采用 Bottom Sheet / Sheet 形态，与当前 Sumly 新增黄金流程保持一致。

### 4.1 默认快速录入

默认只展示：

- 黄金类型
- 克重
- 购买总价 / 购买单价
- 购买日期

用户填写这些字段即可保存。

不要因为加入真实收益能力而强迫用户填写专业参数。

### 4.2 高级信息

提供折叠入口：

> 完善真实收益信息

展开后展示：

- 工费
- 纯度
- 其他成本
- 渠道
- 回收规则

默认保持收起。

### 4.3 即时反馈

表单底部动态展示：

> 按当前回收规则，预计真实保本金价约为 ¥XXX / g

输入发生变化后即时更新。

## 5. 买前算一算

这是 V1 的重点独立交互能力。

入口：

- 记金首页快捷操作

无需先创建持仓。

### 5.1 输入

包括：

- 黄金类型
- 克重
- 商家裸金报价
- 工费
- 回收规则

输入即计算，不设置单独「计算」按钮。

### 5.2 结果

第一结果：

> 预计总支出

随后展示：

- 综合买入成本
- 当前买入溢价
- 真实保本金价
- 距离回本还需上涨多少

默认回收参数参与计算时必须明确显示：

> 当前使用 Sumly 默认回收估算

点击可查看具体参数。

### 5.3 转持仓

底部主 CTA：

> 保存为持仓

点击后将计算器已有字段直接带入新增持仓流程，避免用户重复输入。

## 6. 情景测算

从持仓详情进入。

核心问题：

> 如果参考金价变成某个价格，我这笔黄金会怎样？

### 6.1 价格调整

同时支持：

- Slider 拖动
- 数字输入
- 快捷价格点

快捷点：

- -10%
- -5%
- 当前
- 保本
- +5%
- +10%

### 6.2 实时结果

价格变化时同步刷新：

- 现在卖预计到手
- 真实盈亏
- 真实收益率
- 与保本线的距离

关键数字在拖动过程中实时刷新。

---

## 7. 持仓提醒

从持仓详情进入。

优先提供与个人持仓相关的提醒：

### 达到真实保本

> 这笔黄金达到预计真实保本线。

### 收益率目标

例如：

> 真实收益率达到 10%。

### 盈利金额目标

例如：

> 预计回收盈利达到 ¥3,000。

### 普通价格提醒

继续保留：

> 参考金价达到 ¥XXX / g。

提醒必须由用户主动开启。

---

## 8. 金额隐私

继续保留首页金额隐藏能力。

隐藏后：

- 预计到手
- 总投入
- 盈亏金额
- 单笔金额

统一使用掩码。

克重、百分比等是否隐藏，正式实现时沿用现有 Sumly 隐私规则，不单独创造第二套逻辑。

---

## 9. 视觉规范

直接复用现有 `GoldTheme`。

核心视觉：

- 背景：近黑
- 卡片：深棕黑
- 强调色：Sumly 金色
- 国内习惯：红涨、绿跌
- 大金额使用大号粗体数字
- 卡片圆角延续现有设计
- 主 CTA 使用金底深色文字
- 次 CTA 使用深色背景 + 金色强调

禁止为了新功能单独引入另一套颜色、圆角或组件体系。

 │

         └─ 标记卖出

## 11. iOS 落地约束

正式开发时：

1. 不重构现有底部导航。
2. 优先增量修改现有 `HoldingsView` 和 `AddHoldingSheet`。
3. 真实收益计算必须进入统一纯逻辑计算层，不在 SwiftUI View 中散落公式。
4. 复用 `GoldTheme` 和现有卡片 / Button Style。
5. 现有旧持仓必须继续可用。
6. 新字段需要考虑 SwiftData 本地迁移。
7. 国内 / 国际行情口径继续沿用现有 `GoldMarketBasis`。
8. 当前参考金价、持仓估值、买前计算器必须使用一致的数据口径。
9. 所有核心计算逻辑需要 Swift Testing 单测。
10. UI 完成后使用模拟器截图进行目视验证。

---

## 12. 原型确认结论

本方案已完成第一轮可交互 HTML 原型验证。

确认采用的核心方向：

- 不增加一级 Tab。
- 「记金」升级为真实收益资产入口。
- 首页主指标使用「现在卖预计到手」。
- 保本线成为首页重要但次一级的信息。
- 新增持仓使用「简单录入 + 高级参数折叠」。
- 买前计算器独立存在，并可一键转为持仓。
- 持仓详情承担专业数据解释。
- 情景测算使用 Slider + 快捷价格点。
- 提醒从普通行情提醒升级为个人持仓事件提醒。

后续正式实现以本交互文档与 `gold-real-return-prd.md` 共同作为产品依据。
