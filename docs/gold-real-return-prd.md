# Sumly 黄金持仓真实收益与决策系统 PRD

> 版本：V1.0  
> 日期：2026-09-30  
> 产品定位：**帮你算清每一克黄金真正赚了多少钱。**

---

## 1. 产品结论

Sumly 不以“黄金记账工具”为最终定位，而以 **黄金持仓真实收益计算 + 买卖决策工具** 为核心。

产品贯穿三个阶段：

| 阶段 | 用户问题 | Sumly 核心输出 |
|---|---|---|
| 买之前 | 这件黄金买得贵不贵？多久才能回本？ | 实际买入成本、真实保本金价、需上涨幅度 |
| 持有中 | 账面赚了，但现在真卖掉赚吗？ | 账面价值、预计到手、真实盈亏 |
| 准备卖 | 现在卖能拿多少钱？ | 预计到手金额、真实收益率、回收参数影响 |

核心原则：**先给结论，再给计算过程。**

---

## 2. V1 目标与范围

### 2.1 核心目标

- 用户录入一笔黄金后，能在 10 秒内理解：**投入多少、现在真值多少、何时保本**。
- 把普通“价格提醒”升级为与个人持仓相关的事件提醒。
- 所有专业计算均可解释，用户可以查看计算依据并修改参数。
- 首页保持轻量，不做复杂金融终端。

### 2.2 功能优先级

#### P0：首期必须完成

- 真实持仓成本模型
- 预计回收到手金额
- 真实盈亏 / 真实收益率
- 真实保本金价
- 买前计算器
- 持仓相关提醒
- 计算依据可解释

#### P1：紧随其后

- 多回收渠道参数
- 情景测算
- 收益变化展示
- iOS Widget 展示个人关键指标

#### P2：后续增强

- OCR 小票 / 订单识别
- 目标存金瓶
- Live Activities / 灵动岛
- 社交分享卡片

### 2.3 暂不做

- 社区
- 资讯流
- 复杂交易策略
- 为了“功能多”而增加的泛贵金属功能

## 3. 核心数据模型

### 3.1 单笔持仓字段

| 字段 | 说明 | 要求 |
|---|---|---|
| 黄金类型 | 金饰 / 金条 / 积存金 / 其他 | 必填 |
| 克重 | 实际持有克重 | 必填 |
| 纯度 | 9999 / 999 / 990 等 | 默认预设，可修改 |
| 裸金单价 | 买入时金价 | 可由总价反推 |
| 工费 | 按克或总额 | 可选，默认 0 |
| 其他成本 | 运费、税费、鉴定费等 | 可选 |
| 购买总成本 | 用户实际现金支出 | 系统计算，可人工覆盖 |
| 购买日期 | 用于收益周期计算 | 必填 |
| 渠道 / 品牌 | 银行、专柜、水贝等 | 可选 |
| 回收规则 | 基准价、每克扣减、比例折价、固定费用 | 默认模板，可修改 |

## 4. 核心计算口径

### 4.1 持仓成本

```text
持仓成本 = 裸金成本 + 工费 + 其他成本
```

界面名称：**总投入**

### 4.2 账面价值

```text
账面价值 = 当前参考金价 × 有效克重
```

### 4.3 预计回收单价

概念模型：

```text
预计回收单价
= 回收基准价
- 每克扣减
再应用比例折价
```

实际实现时统一由计算内核处理，避免各页面重复计算。

### 4.4 现在卖预计到手

```text
预计到手
= 预计回收单价 × 有效克重
- 固定卖出费用
```

产品界面优先使用：

> **现在卖预计到手**

不优先暴露“净清算价值”这种术语。

### 4.5 真实盈亏

```text
真实盈亏 = 预计到手 - 持仓成本
```

### 4.6 真实收益率

```text
真实收益率 = 真实盈亏 / 持仓成本
```

### 4.7 真实保本金价

反推满足以下条件时的市场参考金价：

```text
预计到手 = 持仓成本
```

界面显示：

- 真实保本金价：¥X / g
- 当前距离保本：还差 ¥X / g
- 或：已超过保本线 ¥X / g

### 4.8 可信度原则

所有“真实收益”本质上仍然是基于：

- 当前行情
- 当前纯度
- 当前回收规则
- 用户填写成本

得到的 **估算结果**。

因此 UI 必须清晰标注“预计 / 估算”，不得给用户造成保证成交价格的错觉。

# 6. 核心页面与 UI / 交互

## 6.1 首页

首页只回答三个问题：

1. **我有多少黄金？**
2. **现在真卖能拿多少？**
3. **到底赚没赚？**

### 页面结构

#### 顶部总览

展示：

- 总持有克重
- 总投入

支持：

- 一键隐藏金额

#### 核心资产卡片

视觉重点只突出一个主金额：

> **现在卖预计到手 ¥XX,XXX**

辅助展示：

- 真实盈亏：+¥X,XXX
- 真实收益率：+X.XX%

点击进入收益详情。

### 保本状态

示例：

> 距离真实保本还差 ¥18 / g

或：

> 已超过真实保本线 ¥26 / g

点击后通过 Bottom Sheet 展示计算依据。

### 今日变化

展示因金价变化导致的持仓变化，但视觉弱于“真实盈亏”。

### 快捷操作

主入口：

- **记一笔**
- **买前算一算**

位置需要适合单手操作。

### UI 原则

首页不同时突出：

- 总投入
- 账面价值
- 净值
- 回收价值
- 盈亏

等大量数字。

**核心视觉只能有一个重点。**

默认重点：**现在卖预计到手**。

---

## 6.2 新增 / 编辑持仓

最大原则：

> **不能为了真实收益，把普通记账变复杂。**

### 第一层：快速录入

默认只展示：

- 黄金类型
- 克重
- 购买总价 / 购买单价
- 购买日期

普通用户完成这些就可以保存。

### 第二层：完善真实收益

折叠区域：

> 完善真实收益信息

展开后填写：

- 工费
- 纯度
- 其他成本
- 渠道
- 回收规则

### 自动计算

支持：

- 总价 → 自动反推综合单价
- 单价 + 克重 + 工费 → 自动计算总投入

自动推导值允许用户覆盖。

人工覆盖后显示轻量标识：

> 手动

### 保存前反馈

页面底部动态提示：

> 按当前回收规则，预计真实保本金价约为 **¥871 / g**

让用户在保存之前就感受到新功能价值。

---

## 6.3 持仓详情

### 第一视觉层级

只展示三个核心结果：

- **真实盈亏**
- **现在卖预计到手**
- **真实保本金价**

### 第二层级

展示：

- 总投入
- 账面价值
- 预计回收价
- 真实收益率

### 第三层级：怎么算的？

点击：

> 怎么算的？

弹出 Bottom Sheet，展示：

- 当前参考金价
- 金价来源 / 更新时间
- 克重
- 纯度
- 工费
- 回收扣减
- 其他费用
- 最终公式

目的不是教育用户金融公式，而是让数字 **可信、可解释**。

### 页面操作

- 编辑
- 情景测算
- 设置提醒
- 标记卖出

---

## 6.4 买前计算器

这是 V1 的重要差异化功能。

不要求创建持仓，也不要求登录后建账才能使用。

### 输入

- 黄金类型
- 克重
- 报价
- 工费
- 可选回收规则

### 即时输出

#### 预计总支出

例如：

> ¥29,100

#### 综合买入成本

> ¥970 / g

#### 当前买入溢价

> 相比当前参考金价高 ¥XX / g

#### 真实保本金价

> ¥1,032 / g

#### 回本条件

> 当前参考价还需上涨约 6.4%

### 文案原则

不使用：

- 值得买
- 不值得买
- 推荐购买
- 不建议购买

Sumly 给用户 **事实和计算结果**，不替用户做购买决策。

### 转持仓

提供主 CTA：

> **保存为持仓**

用户购买后无需重新输入一次。

---

## 6.5 情景测算

目的：

> 如果黄金涨到某个价，我到底赚多少？

### 交互

支持：

- 滑杆
- 数字直接输入

快捷价格点：

- -10%
- -5%
- 当前
- 保本
- +5%
- +10%

### 实时展示

随着价格变化：

- 预计到手
- 真实盈亏
- 真实收益率

实时变化。

滑杆拖动过程中优先刷新关键数字。

复杂图表可以等用户松手后再刷新，避免卡顿。

---

## 6.6 持仓相关提醒

传统提醒：

> 金价到了 ¥900

升级为：

> **你的黄金现在达到真实保本线了。**

### 支持提醒

#### 达到真实保本

> 你的 30g 手镯已达到预计真实保本线

#### 达到收益率

> 这笔持仓预计真实收益率达到 10%

#### 达到盈利金额

> 现在回收预计可盈利 ¥3,000

#### 普通价格阈值

> 参考金价达到 ¥900 / g

### 防骚扰

必须支持：

- 用户主动开启
- 同一提醒冷却
- 穿越阈值判断
- 异常行情不触发
- 避免价格在阈值附近反复推送

# 7. UI / UX 设计原则

## 7.1 结论先于数据

不要一进入页面就看到十几个金融指标。

顺序：

> 结果 → 原因 → 参数 → 公式

---

## 7.2 渐进式复杂度

新用户看到简单工具。

高级用户可以继续展开专业能力。

不能让“专业”变成“难用”。

---

## 7.3 减少专业术语

优先：

> 现在卖预计到手

而不是：

> 净清算价值

优先：

> 你还差 ¥18 / g 保本

而不是只显示：

> Break-even Price：¥871

---

## 7.4 输入即反馈

用户修改：

- 克重
- 单价
- 工费
- 回收扣减

结果立即更新。

尽量不要让用户反复点击“计算”。

---

## 7.5 默认值必须透明

如果用户不知道回收折价，可以使用默认值。

但必须明确告诉用户：

> 当前使用 Sumly 默认回收估算

而不是悄悄参与计算。

---

## 7.6 单手操作

高频操作：

- 新增
- 计算
- 保存
- 设置提醒

尽量放在底部安全区附近。

---

## 7.7 隐私

黄金资产金额属于敏感信息。

需要：

- 首页金额一键隐藏
- Widget 提供不显示资产金额的模式
- 分享截图时考虑隐私保护

---

# 8. 空状态和异常状态

| 状态 | UI 处理 |
|---|---|
| 没有持仓 | 主 CTA：记第一笔黄金；次 CTA：先算一算 |
| 无实时行情 | 使用最后有效价格，显示更新时间并标记“非实时” |
| 无回收规则 | 使用默认估算模板，并提示可以修改 |
| 数据不完整 | 仍允许保存，但真实收益标记为“估算” |
| 行情异常 | 暂停相关提醒，避免错误推送 |

---

# 9. 回收模型设计

V1 **不要**把“市场一般扣 5~10 元 / g”直接硬编码成事实。

回收规则必须参数化。

建议：

```text
LiquidationRule
- benchmark_type
- per_gram_deduction
- discount_rate
- fixed_fee
- updated_at
```

区分：

- Sumly 默认估算
- 用户自定义规则

模板未来可以按：

- 金条
- 金饰
- 积存金
- 银行
- 品牌专柜
- 水贝 / 黄金回收渠道

进一步细化。

未来如果有真实渠道报价，可直接扩展到实时报价体系。

# 11. 产品验证指标

首期不需要大量埋点，只观察几个关键指标：

| 指标 | 验证问题 |
|---|---|
| 首次持仓创建完成率 | 新录入是否足够简单 |
| 高级参数展开率 | 用户是否关心真实成本 |
| 买前计算器使用率 | 核心差异化场景是否成立 |
| 计算器 → 保存持仓 | 买前到持有闭环是否成立 |
| 保本提醒开启比例 | 个性化提醒是否有价值 |
| 7 / 30 日回访 | 是否比普通黄金记账更有持续使用价值 |

# 13. V1 验收场景

### 场景 1：最简单的用户

用户只知道：

- 30g
- 总价 ¥25,800
- 购买日期

也可以直接保存并得到基础估算。

### 场景 2：高级用户

补录：

- 工费 ¥80 / g
- 回收每克扣 ¥8

系统立刻重新计算：

- 总投入
- 真实盈亏
- 真实保本金价

### 场景 3：购买之前

用户输入：

- 30g
- 当前报价
- 工费

直接得到：

- 综合买入成本
- 当前溢价
- 保本金价
- 需要上涨多少才回本

### 场景 4：达到保本线

推送：

> 你的这笔黄金已达到预计真实保本线。

而不是仅推送：

> 金价达到 ¥XXX。

### 场景 5：行情异常

行情源失效时：

- UI 显示最后更新时间
- 标记非实时
- 不触发错误提醒

# 14. 实现约束

正式开发前需要结合当前 Sumly 项目确认：

- 当前 iOS 导航结构
- 当前持仓模型
- 当前金价数据源
- 服务端数据结构
- 当前设计系统
- 当前通知实现
- 当前 Widget 能力
- 当前订阅体系

实现原则：

1. **优先增量修改，不为了 PRD 重写现有稳定架构。**
2. 复用当前组件和设计语言。
3. 如果设计 token 不完整，再抽取统一的：
   - 颜色
   - 字体
   - 间距
   - 圆角
   - 阴影
4. 新功能不能看起来像被硬塞进现有 App 的独立模块。
5. UI 实现前需要结合现有 Sumly 页面逐页确认最终交互，而不是机械照搬本文档。

# 15. 核心定位总结

Sumly 的核心不是：

> 帮用户记录买了多少黄金。

而是：

> **让用户在买之前、持有期间和准备卖出时，都能真正算清这笔黄金的钱。**

核心差异化最终收敛到三件事：

1. **真实收益，而不是表面浮盈**
2. **真实保本线，而不是单纯看金价**
3. **个人持仓事件，而不是泛行情提醒**

这三点应优先于 Widget、OCR、灵动岛和社交功能。
